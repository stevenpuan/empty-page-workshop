## 2. 核心流程

### 進貨→應付流程

```
建立採購單 (draft)
  ├─ source_type='stock'：庫存補貨，不關聯工單
  └─ source_type='direct'：直接採購，關聯工單

確認採購單 → confirm_purchase(id)
  ├─ status: draft → confirmed
  ├─ 自動產生 payable（doc_no 由 next_doc_no 生成）
  ├─ 到期日依廠商 payment_term 由 calc_due_date() 推算
  └─ source_type='direct' 時：自動寫入 order_costs（cost_type=material）

作廢採購單 → void_purchase(id)
  ├─ 檢查：對應應付不可已有付款
  ├─ 應付 status → void
  └─ 移除 order_costs 記錄
```

### 付款沖帳流程

```
建立付款 → allocate_payment(...)
  ├─ 傳入 allocations JSON: [{"payable_id":"...", "amount":123}, ...]
  ├─ 驗證：沖帳總額 = 付款金額
  ├─ 逐筆 FOR UPDATE 鎖定應付（防併發）
  ├─ 各應付 paid_amount 累加，status 自動切換：
  │   └─ unpaid → partial → paid
  └─ 不允許超付

作廢付款 → void_payment(id)
  ├─ 逐筆反沖：各應付 paid_amount 扣回
  ├─ status 自動退回：paid → partial → unpaid
  └─ 刪除 payment_allocations
```

### 到期日推算規則（calc_due_date）

| payment_term | 說明 | 範例（base 9/10） |
|---|---|---|
| cash | 即期 | 9/10 |
| net30 | +30 天 | 10/10 |
| net60 | +60 天 | 11/9 |
| net90 | +90 天 | 12/9 |
| monthly_15 | 次月 15 日 | 10/15 |
| monthly_end | 次月月底 | 10/31 |

## 3. RPC 函式簽名

```sql
-- 進貨確認
confirm_purchase(p_purchase_id uuid) → jsonb
-- 回傳：{success, purchase_id, payable_id, payable_doc_no, due_date}

-- 進貨作廢
void_purchase(p_purchase_id uuid) → jsonb
-- 回傳：{success, purchase_id}

-- 付款沖帳
allocate_payment(
  p_company_id uuid, p_vendor_id uuid, p_pay_date date,
  p_method text, p_amount numeric,
  p_allocations jsonb,  -- [{"payable_id":"...", "amount":123}]
  p_bank_account text?, p_check_no text?,
  p_check_due_date date?, p_note text?, p_created_by uuid?
) → jsonb
-- 回傳：{success, payment_id, payment_no, allocated_count}

-- 付款作廢
void_payment(p_payment_id uuid) → jsonb
-- 回傳：{success, payment_id}
```

## 4. Lovable 前端指令

### 指令 K：進貨單頁面 `/purchases`

```
請建立進貨單管理頁面 src/pages/purchases.tsx，功能如下：

1. 列表頁
   - 查詢：supabase.from('purchases').select('*, vendor:vendors(name, vendor_code), items:purchase_items(*)').eq('company_id', currentCompanyId).order('created_at', {ascending: false})
   - 欄位：採購單號、廠商、進貨日、來源(stock/direct)、稅別、未稅額、稅額、合計、狀態
   - 篩選：狀態（全部/draft/confirmed/void）、廠商
   - draft 狀態的單可點進編輯，confirmed/void 唯讀

2. 新增/編輯表單（Dialog 或獨立頁）
   - 表頭：廠商（下拉 vendors）、進貨日、來源類型（stock 庫存補貨 / direct 直接採購）
   - source_type='direct' 時顯示「關聯工單」下拉（查 orders where status != 'completed'）
   - 發票號碼、發票日期
   - 稅別（應稅 taxable / 零稅率 zero / 免稅 exempt）
   - 明細列表（purchase_items）：品項名稱、規格、數量、單位、單價、金額（自動計算）、是否入庫
   - 可動態增減明細列
   - 表尾自動彙算：未稅小計、稅額（taxable 時 = 未稅×5%，其餘 0）、合計
   - 儲存時同時寫入 purchases + purchase_items，purchase_no 由 next_doc_no(company_id, 'PO') 產生
   - 呼叫方式：const { data } = await supabase.rpc('next_doc_no', { p_company_id: companyId, p_doc_type: 'PO' })

3. 確認按鈕
   - 只有 draft 狀態顯示
   - 點擊呼叫：await supabase.rpc('confirm_purchase', { p_purchase_id: id })
   - 成功後顯示回傳的 payable_doc_no 和 due_date
   - 重新載入列表

4. 作廢按鈕
   - 只有 confirmed 狀態顯示
   - 二次確認 Dialog
   - 呼叫：await supabase.rpc('void_purchase', { p_purchase_id: id })

5. 金額格式統一用 formatTWD()，右對齊
6. RLS 會自動過濾，不需前端加 company_id 以外的權限判斷
```

### 指令 L：應付與付款頁面 `/payables`

```
請建立應付與付款管理頁面 src/pages/payables.tsx，分兩個 Tab：

     p_vendor_id: vendorId,

     p_method: method,
     p_amount: totalAmount,
     p_allocations: JSON.stringify(allocations),
     p_bank_account: bankAccount,
     p_check_no: checkNo,
     p_check_due_date: checkDueDate,
     p_note: note,
     p_created_by: currentUserId
   })
4. 付款記錄列表：
   - 查詢 payments + payment_allocations
   - 欄位：付款單號、廠商、付款日、方式、金額、狀態
   - 展開可看沖帳明細（哪些應付沖了多少）
5. 作廢付款按鈕（confirmed 狀態）：
   - 二次確認：「作廢將反沖所有已沖帳金額，確定？」
   - 呼叫：await supabase.rpc('void_payment', { p_payment_id: id })

金額格式統一用 formatTWD()
```
