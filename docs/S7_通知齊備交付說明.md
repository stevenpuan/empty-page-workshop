## 架構說明

### 雙入口觸發

```
事件型（event）                          掃描型（scan）
DB trigger → trg_notify_xxx()           pg_cron → cron_guarded('notify_scan_all')
         ↓                                        ↓
    emit_notification()              10 條 SQL 掃描 → emit_notification()
         ↓                                        ↓
  INSERT notifications              INSERT notifications
         ↓                                        ↓
  trg_notifications_line_push       trg_notifications_line_push
  (line_mode=immediate 時推播)      (line_mode=immediate 時推播)
```

### LINE 推播流程

```
notifications INSERT (line_status='pending', line_mode='immediate')
  → trg_notifications_line_push trigger
    → call_edge_function('line-push', {notification_id, ...})
      → pg_net async HTTP POST → line-push Edge Function
        → LINE Messaging API push
        → 回寫 line_status = 'sent' / 'failed'

每日 08:00 (UTC+8):
  pg_cron → send_line_digests()
    → 彙總 line_mode='digest' & line_status='pending' 的通知
    → 按 employee 分組 → call_edge_function('line-push', {notification_ids, ...})
    → LINE 推播批次摘要
```

### 去重機制 (dedupe_key)

- 格式：`{rule_code}:{ref_id}:{employee_id}:{suffix}`
- 唯一索引：`ON CONFLICT DO NOTHING`
- scan 型：suffix 依規則不同
  - `once` — 只觸發一次（payable_due_soon, receivable_due_soon, clock_in_missing）
  - `d{N}` — 每 N 天觸發一次（payable_overdue 每5天, receivable_overdue 每3天）
  - 空白 — 每次掃描都觸發（task_overdue, task_blocked 等）
- event 型：suffix 為空，每次事件都產生通知

## Edge Function 說明

### line-push

- 路徑：`/functions/v1/line-push`
- 認證：Bearer token（service_role_key 或 INTERNAL_PUSH_KEY）
- 功能：接收 notification_id（單筆）或 notification_ids（批次），讀取 notification 內容，透過 LINE Messaging API push 給員工的 LINE UID
- LINE Channel：由 `companies.line_channel_key` 決定，環境變數 `LINE_CHANNEL_TOKEN_{KEY}`

### notify-dispatcher

- 路徑：`/functions/v1/notify-dispatcher`
- 認證：Bearer token（service_role_key 或 INTERNAL_PUSH_KEY）
- 功能：手動觸發 `notify_scan_all()`，回傳產生的通知總數
- 用途：測試/除錯時手動執行掃描

## 前端 Lovable 指令

### 指令 S — 通知規則設定頁 `/settings/rules`

```
請建立通知規則設定頁面 /settings/rules，僅 manager 和 owner 角色可見。

## 頁面功能

讓管理者設定各類通知規則的啟用狀態、推播方式。

## 資料來源

查詢當前公司的通知規則：
```js
const { data: rules } = await supabase
  .from('notification_rules')
  .select('*')
  .order('category, rule_code');
```

## 頁面結構

按 category 分組顯示規則卡片：

分組標題對照：
- dispatch → 派工通知
- outsource → 外包通知
- payable → 應付帳款
- receivable → 應收帳款
- attendance → 出勤通知
- system → 系統通知

每張規則卡片顯示：
- 規則名稱（name 欄位）
- trigger_kind badge：event=藍 / scan=灰
- 主開關：is_enabled（toggle switch）
- 站內通知開關：in_app_enabled（toggle switch）
- LINE 推播開關：line_enabled（toggle switch）
- LINE 推播模式：line_mode（immediate=即時推播 / digest=每日摘要）— 用 radio 或 select
- 接收人範圍：recipient_scopes（顯示用，格式如 ["owner", "manager"]）

## 更新邏輯

每個 toggle 或選項變更時，呼叫 RPC：
```js
const { error } = await supabase.rpc('update_notification_rule', {
  p_rule_id: rule.id,
  p_is_enabled: newValue,       // 只傳變更的欄位
  // p_in_app_enabled: ...,
  // p_line_enabled: ...,
  // p_line_mode: ...,
});
```

參數只傳有變更的欄位，其餘傳 null（RPC 會 coalesce 保留原值）。

## 設計風格

- 每個分組用 Accordion 或 Section 區隔
- 規則名稱放左側，開關和選項放右側
- 使用一致的 toggle switch 樣式
- 當 is_enabled = false 時，其餘開關灰顯不可點
- 當 line_enabled = false 時，line_mode 灰顯不可點

## 權限控制

```js
if (currentRole !== 'owner' && currentRole !== 'manager') {
  navigate('/');
  return;
}
```
```

### 指令 T — 通知鈴鐺 + 通知中心（Sidebar）

```
請在 Sidebar 加入通知鈴鐺圖示，並建立通知中心下拉面板。

## 鈴鐺 icon

在 Sidebar 頂部或 header 區域加入 Bell icon：
- 使用 my_notification_count view 取得未讀數：
  ```js
  const { data } = await supabase
    .from('my_notification_count')
    .select('unread_count')
    .single();
  ```
- 未讀數 > 0 時，在 Bell icon 右上角顯示紅色數字 badge
- 未讀數 = 0 時，不顯示 badge

## 通知面板

點擊鈴鐺後，展開通知面板（可用 Sheet / Popover / Dropdown）：

### 頂部
- 標題「通知」
- 「全部標記已讀」按鈕（右上角）：
  ```js
  await supabase.rpc('mark_all_notifications_read');
  ```

### 通知列表

查詢：
```js
const { data: notifications } = await supabase
  .from('notifications')
  .select('*')
  .order('created_at', { ascending: false })
  .limit(50);
```

每筆通知顯示：
- title（粗體）
- body（一行，超出截斷）
- 時間（相對時間：3分鐘前、2小時前、昨天等）
- 未讀狀態：左側或底色區分（未讀=淺藍底 / 已讀=白底）
- LINE 狀態 icon（可選）：sent=✓ / failed=✗ / pending=⏳

### 點擊通知

點擊某筆通知：
1. 呼叫標記已讀：
   ```js
   await supabase.rpc('mark_notification_read', {
     p_notification_id: notification.id
   });
   ```
2. 根據 ref_type 導航到相關頁面：
   - order_task → `/orders/{ref_id}` 或工單詳情
   - attendance → `/attendance`
   - payable → `/payables`
   - receivable → `/receivables`
   - employee → `/employees`
   - 無匹配 → 不導航，僅標記已讀

## 即時更新

使用 Supabase realtime 監聽新通知：
```js
supabase
  .channel('notifications')
  .on('postgres_changes', {
    event: 'INSERT',
    schema: 'public',
    table: 'notifications',
    filter: `employee_id=eq.${currentEmployeeId}`
  }, (payload) => {
    // 新通知加到列表頂部
    // 更新未讀數
    // 可選：顯示 toast 提示
  })
  .subscribe();
```

## 設計風格

- 鈴鐺 icon 大小適中，badge 用紅色小圓點+數字
- 通知面板最大高度限制，超出時滾動
- 未讀與已讀用底色清楚區分
- 載入中顯示 skeleton
- 無通知時顯示空狀態圖示+文字
```
